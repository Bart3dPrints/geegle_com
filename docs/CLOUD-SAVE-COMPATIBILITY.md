# Geegle save compatibility and rollout

- Ohflip, Quantum Clicker, and Spacebar Clicker are the only audited automatic adapters. When an account has no save locally or in the cloud, the player offers to copy older, unassigned browser progress **before** the game starts. Users must confirm that it is theirs. The original browser save remains accessible when signed out. A copy never overwrites an existing save.
- Account settings can export all cloud rows, including unrecognized games, slots, and IndexedDB payloads, without converting or modifying them. IndexedDB export is an archive, not an automatic import into the game. Local-only games still use their original storage and game-provided export controls, where available.
- Unassigned favorites, recent games, theme, and server defaults remain in the signed-out profile. Account Settings can export them along with the three audited games’ older device saves and saves scoped to the current account. They are not added or applied to an account on sign-in.
- Before the revision migration, cloud reads, restores, exports, and first-save inserts still work. An existing cloud row cannot be updated until migration 0002 is installed: older clients can change a payload without bumping its timestamp. New device progress stays local and can be exported. Relaunch the game after applying the migration. Already-open old frontends can still write unconditionally, so refresh old sessions during rollout.
- Namespacing keeps the three audited games from automatically sharing progress between accounts. It is **not** browser security isolation. Same-origin game scripts can access the app's storage, including its session; games that use shared, unassigned device storage may show the same local data to different users. Do not run untrusted builds in a signed-in Geegle session on the app origin.

## Origin isolation follow-up

An iframe sandbox without `allow-same-origin` blocks access to the parent, but also denies the frame access to its existing localStorage/IndexedDB and can break game launch. Adding `allow-same-origin` to a script-enabled iframe on the app origin does not isolate it. See [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox).

Serve games from a separate games origin without application credentials or shared authentication cookies. Keep game storage available on that origin, and implement a narrowly scoped bridge for each audited game: verify iframe source window and exact game-host origin; bind requests to the active game and verified session; transfer validated game data only, never tokens. Introduce it per game after verifying launch, legacy progress migration, browser storage partitioning and offline saves. No separately deployed game origin was added by this patch.
