# Artwork completion report

Generated by `scripts/artwork/report.py` from the machine-readable manifest (`scripts/artwork/progress.json`, `audit.json`, `captured.json`, `review.json`). Counts are recomputed, never hand-typed.

## Scope and method

Artwork only: cards, search results, favorites and Recently Played all read the same `artworkFor()` record, so a verified image appears everywhere the title appears. No catalog ID, launch path, save key or layout was changed.

Acquisition order, enforced per title: (1) authentic icon or official social image declared by the game's own distribution; (2) authentic logo/game asset from that build; (3) authentic gameplay artwork; (4) a captured title screen or recognizable gameplay frame from the actual build this repository serves, with engine splashes, loading screens, error pages, ads and generic play splashes rejected.

Identity evidence and reuse basis are recorded separately on every record. Captured frames carry no license claim; they are the game's own screen shown on the same platform and are removed on request. Licensed records carry a pinned license notice.

## Incorrect existing images replaced

The pre-existing set was audited rather than trusted. 35 of 73 records were rejected before counting any coverage: repeated portal logos assigned to many unrelated titles, blank or near-uniform crops, loading screens and mismatched artwork. Those records were pruned from the runtime index and are replaced through the same acquisition order. 

Rejection reasons recorded:

- 13x Every qualifying frame carried the mod's flashing-lights warning dialog, which is not acceptable artwork.
- 12x Every qualifying frame was still a loading screen or a half-loaded engine frame inside the 15-second window.
- 11x Every qualifying frame was a publisher, portal or engine splash, not the game's own screen.
- 7x The frame shows only the shared Friday Night Funkin base logo, which does not identify this specific mod.
- 6x Every qualifying frame was still a loading screen (progress bar or "Loading n/m"), so nothing finished could be captured in the 12-second window.
- 5x Every qualifying frame carried a consent, language, license or age dialog over the content.
- 4x Every qualifying frame carried a consent, age, profanity, legal or ad-block dialog over the content.
- 4x The frame is an empty background with no legible title or gameplay.
- 4x The frame is a publisher or engine splash, not the game's own screen.
- 3x Every qualifying frame was an error page ("Something went wrong"), which is never acceptable artwork.
- 3x Every qualifying frame was an error page ("Something went wrong", a 404 loader), which is never acceptable artwork.
- 3x Still a loading screen when the 15-second window ended.

## Honest limitations

- Captured title screens depend on the third-party build actually loading; slow emulators and Flash wrappers may need a longer wait before a usable frame exists.
- Automated checks reject blank, uniform, duplicated and low-information frames, but every accepted image was also inspected on a generated contact sheet before being marked verified.
- No image is counted because its file exists: verification requires a matching title, decodable bytes and a visual check.
